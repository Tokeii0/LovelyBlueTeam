# 上传攻击、JSP 与内存马处置

触发信号包括上传接口异常、上传目录出现脚本、同一文件的回访、异常 JVM 子进程、可疑 Filter/Listener 或关联出站连接。

1. 采集访问日志、POST 原文、后端日志、落地目录和进程信息。按请求 ID、时间、文件名和哈希建立关联，先保全原始证据。
2. 区分上传请求、接口返回、文件落地、脚本访问、实际执行与持久化六个阶段。HTTP 200 或 JSON “success” 只证明接口响应，404 也不能证明历史从未落地。
3. 缓解优先限定明确接口和目录：授权上传、扩展名白名单、随机命名、存储与执行分离。Nginx/上传 Lua 与 Tomcat 上传应用禁脚本作为分层缓解。
4. 在取证副本静态分析 JSP/Class、编码与加密参数。用明确密钥解密时记录算法、来源与完整性校验；不执行未知样本或还原出的命令。
5. 经变更批准隔离或清理落地文件。JSP Cleaner 默认预览，永久删除前必须留样。检查内存中的注册项、编译缓存、计划任务及其他持久化，补丁后受控重启。
6. 从相同入口和真实业务路径复测，观察回访、进程与出站连接。关闭工单需同时满足根因修复、影响核查与业务恢复。

输出：事件时间线、文件 SHA-256、执行证据、受影响范围、临时措施、根本修复、复测和未确认事项。原始样本与密钥不得作为公开报告附件。
