# 隔离蜜罐值守

目标是观察进入自有诱饵服务的请求，训练事件关联、分级、留证与复盘。VPN 和 UDS 公开版使用合成数据，终端程序不采集访问者设备信息。

演练前阅读[红队心理与流程设计](../docs/honeypot-design.md)及 [AI Agent 自动执行风险](../docs/ai-agent-workflows.md)。将“读取材料”“计划命令”“实际执行”“服务端收到请求”分别记录；离线 CLI 不产生回传事件，执行证明来自测试端主动留存的记录。

1. 在独立主机或网络区启动[蜜罐模块](../honeypots/README.md)，记录版本、监听地址、负责人和测试窗口；边界禁止连接业务数据库及文件共享。
2. 自测一次成功/失败登录、未知路由、超限请求和注销，确认事件时间、状态与路由完整。CLI 输出中的成功状态仅为模拟结果。
3. 观察同一时间段的失败登录增长、异常方法、未知路径与超限事件；`peer_tag` 仅能在同一服务的本次进程内关联，反代后会聚合为代理来源。
4. 对可疑访问使用受控 WAF 日志关联，记录证据与假设。一次访问不能证明入侵成功，演示令牌不能当作凭据失陷证据。
5. 需要处置时先核对资产授权和业务影响，再按变更单人工确认；蜜罐事件不直接触发自动封禁。
6. 定期检查磁盘与容器日志轮转，停用时关闭本次服务进程/容器并撤销边界映射。按保留策略归档或清理运行事件；源码包只包含人工合成例子。

采用[事件报告](../templates/incident-report.md)与[证据清单](../templates/evidence-register.md)记录观察窗口、固定路由、状态、时间关联和不确定性。不得将门户收到的密码、会话、源 IP 或业务信息复制进公开案例。
