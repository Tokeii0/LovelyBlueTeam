# 路径绕过与网关规则核查

围绕同一请求同时保留原始路径、代理规范化后的 URI、后端路由、方法与响应。重点检查点段、编码斜杠、分号路径参数、双重编码、大小写后缀、Context 映射及代理 location 优先级。

先复核真实请求经过哪个 server/location，以及前置 rewrite/return 是否提前生效。将拦截条件作用于明确范围，保留正常 `;jsessionid=`、业务回调、OPTIONS 和附件下载的回归用例。不要仅根据浏览器跳转页面判断后台被阻断。

对 OpenResty，检查各阶段 Lua 的继承关系；server 已有 rewrite_by_lua_block 时，新增模块应合并进入该块。更深的 location 声明同阶段处理器可能覆盖原防护。先 `nginx -t` 再通过正常与异常请求验证实际命中，测试失败立即回滚。

记录变更前后：路由、状态码、上游是否收到请求、日志 request_id、错误率、业务回调结果。仅有配置语法通过时，将结论写为“语法有效，运行行为待验证”。
