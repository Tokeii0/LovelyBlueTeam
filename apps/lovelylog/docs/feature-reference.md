# LovelyLog 功能参考

## 日志与解析

通过 1Panel API 按字节读取配置的 post.log，首次读取末尾指定行数；默认 200 行、3 秒轮询。bbolt 同时保存日志和断点，半行等待补齐；检测轮转后重新建立文件代际。日志必须为 JSON 行，主要字段为 time、ip、method、uri、status、content_type、body、upstream 和 duration。

记录保留原文及 SHA-256，可搜索、筛选、查看原文/还原结果、送审预览和报告。UI 暂停不会停止采集。运行库不自动清理，包含原始正文与解密结果，需私有存储与备份。

## 解密规则

crypto_profiles 为空时不尝试猜密钥。每条规则须给定明确的 path_regex、算法、字段和密钥来源，可选 prefix_bytes/suffix_bytes。

支持 AES-CBC / AES-ECB 的严格 PKCS7 校验；ECB 仅用于兼容既有协议，不建议用于新业务。密钥/IV 用原始字节的标准 Base64 填入私有配置；source_jsp 可从已知样本文本提取参数，样本只作静态解析，不执行代码。

RSA-AES-GCM 四段封装需标准 RSA 私钥与指定 RSA padding，只有 GCM 认证成功且内容可识别才标记解密成功。仅凭四段形状不能确认算法，不完整或非标准密钥不能当作有效 RSA 私钥。

递归处理对象、数组与 JSON 字符串中的 body/body_content，展开结构化 URL/Base64 与 gzip，设有深度与大小限制。编码还原、密码学解密、后端日志关联分别标识。缺失、截断、未解密与部分还原不能混作完整明文。

## 后端精确关联

工具 check_backend_plaintext.py 在指定的授权后端日志中匹配相同密文的 SHA-256，再校验后端流水、操作标签、同秒和相邻行约束，剔除冲突映射。结果包含明文，必须保存在公开仓库之外。

BACKEND-LOG 配置使用私有 lookup_file 还原精确相同的历史密文；记录来源行与明文哈希。它不推导业务密钥，也不能解开没有匹配项的新密文。随机加密的新请求需要新的后端关联证据或正确密钥。

## 检测、送审与联动

默认 analysis_mode=local；共享 Livelog 配置为 local 时也会强制本地。普通本地检测覆盖 SQL 注入、命令执行、路径穿越、JNDI、脚本/Class 和敏感路径等特征，有限轮次规范化但不执行载荷。规则命中是复核线索，不能单独证明攻击成功。

defense 默认关闭。开启后先脱敏，再以专用 Agent 令牌送入本机 Livelog。需要在 Livelog 中登记 LOCAL_RULE_AGENT_IDS 并确认来源为 local、自动拉黑关闭；不匹配时保留队列并暂停发送。其他采集源的模式独立配置。

恢复 AI 后补充文字分析可处理单条或最多 10 条记录，界面先展示送审载荷。已知密码、令牌、账号及人员/医疗支付字段会遮盖，未知字段仍须人工核对。模型失败与截断响应不缓存；有效报告按完整送审请求、模型、端点及配置缓存，内容或配置变化会重新分析。

自动防护回执显示当时的解析版本、模型、证据和处置结果。WAF 已列入不代表 AF 已同步；没有成功回执不显示已封禁。

## 重处理与测试

停机后可运行 `LovelyLog.exe -config config.local.json -reprocess -once` 批量重新解析。此过程保留原始日志，更新解析结果、特征并清理过时补充报告；不重放已经送审的请求。

公开测试包含人工生成 AES/GCM、gzip、嵌套字段、来源隔离、缓存与 HTTP 边界用例。私有历史测试默认跳过，只在显式提供目录时执行；其原始样本、密文与结果不进入公开包。
