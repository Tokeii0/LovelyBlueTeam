# 数据、证据与留存

先确定现场时区、采集时间和源时间，报告统一写带偏移的时间。每条证据登记来源系统、文件名或记录 ID、行号/偏移、采集方式、SHA-256、采集者和保存位置；原始材料只读保存，分析副本与对外版分别记录。

Livelog 的 SQLite、LovelyLog 的 bbolt、Agent 队列均可能含完整原文。备份前正常停止相应进程，确认不再写入，再复制数据库与配套状态；不要在写入中仅复制 SQLite 主文件而遗漏 WAL。恢复演练在隔离目录进行，先验证记录数、断点和密钥引用，再恢复采集。

按组织要求制定日志、正文、缓存、密钥和备份的保留期限。仓库不预设合法期限，也不启用静默清理。每日检查使用量、增量和最老未处理队列；磁盘紧张时先安全停止采集并保全证据，避免直接删除运行中的数据库。

对外报告使用事件代号、资产代号和泛化时间，去除人员身份、唯一 UA、账号、患者资料、内部域名、证书路径、坐标、群号和可定位现场的截图。保留原始值到代号的对应表只用于内部授权核对，不随报告发送。

蜜罐事件只含最小化访问摘要，`peer_tag` 在重启后变化且不是人员标识。原始路径、正文、账号口令、Cookie 和终端资料不进入事件日志；反代后只能看到代理对端摘要。文件日志模式没有自动轮转，应在本地落实保留和容量策略。UDS `diagnose/export` 产物虽为合成数据，也应留在工作目录，避免混入后续真实运行信息；发布扫描会拒绝默认命名的产物。
